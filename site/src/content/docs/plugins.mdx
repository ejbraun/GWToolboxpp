Open <ToolboxPath steps={["Settings", "Plugins"]} /> to load or unload plugins. This fork explicitly supports its distributed DBBox and SCTracker plugins. Report fork/plugin issues to the fork maintainer with the exact build and reproduction steps.

GWRLauncher manages installation and updates for artifacts supported by its backend. Toolbox discovers DLLs in `Documents/GWToolboxpp/<ComputerName>/plugins`; **Refresh** rescans the directory. A first-time installation does not automatically load or enable a plugin in a running client; use the normal refresh/load or startup behavior. Use **Load** or **Unload** beside a plugin. Only load artifacts from authors you trust, since plugins execute code inside the game process.

DBBox reports its integer version in the plugin list and Windows file properties. Existing plugins without version metadata can still load under their existing interface.

## DBBox features

Expand DBBox to enable or disable individual features. Each has its own instance, settings and shutdown lifecycle. **Stopping...** means pending work is draining. Visibility hides a feature's UI without disabling it.

The [Tactical Minimap](/docs/tactical_minimap/) is disabled by default and has its own opacity, controls and renderer. Its settings do not modify Toolbox's built-in minimap or Mission Map.

## Updates and crash reports

[GWRL](/docs/gwrl/) displays pending updates and lets you request one in game. This fork implements the [protocol](/docs/gwrl_protocol/); launcher integration and live-client acceptance testing are still required.

For plugin-only updates, the launcher coordinates every client sharing a selected outdated plugin file. Toolbox uses its normal settings-save/unload path, then reloads only selected plugins that the particular instance previously had loaded. Manual loading/unloading of those selected plugins is held during the transaction; other plugins and saved enabled selections are not changed by the update.

When Toolbox itself is updated, GWRL requests its normal full exit. After verified replacement and reinjection, Toolbox restores its own settings and plugin selections through normal startup. The launcher does not maintain a separate snapshot of Toolbox's plugin state.

This fork attempts to write crash dumps with plugins loaded. Share dumps manually with the fork maintainer, with build/version, plugin list, enabled DBBox features and reproduction steps. Disabling features individually can help isolate a fault; it is not required to generate a dump.
